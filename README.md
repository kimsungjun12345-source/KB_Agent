# KB_Agent — 보험 리스크 진단·보장 공백 분석 MVP

사용자 정보를 단계적으로 모아 위험을 진단하고, 기존 보장과의 차이를 보여준 뒤 보험상품 정보를 탐색하도록 설계한 대화형 AI 서비스 시제품입니다. **실제 보험 상담이나 가입 권유를 제공하는 상용 서비스는 아닙니다.**

## 한눈에 보기

| 항목 | 내용 |
| --- | --- |
| 해결하려는 문제 | 복잡한 보험 정보를 사용자가 자신의 위험과 보장 상태에 연결해 이해하기 어려움 |
| 핵심 흐름 | 정보 수집 → 리스크 분석 → 보장 공백 분석 → 고지의무 안내 → 상품 탐색 → 질의응답·조정 → 결과 |
| 구현 | Next.js 16, TypeScript, React, Recharts, OpenRouter를 통한 LLM 호출 |
| 상태 | 산학협력 프로젝트 MVP. 상용 서비스 검증 전 단계 |

## 실제 구현에서 볼 부분

- [대화 API](app/api/chat/route.ts): 단계 전환, 모델의 도구 호출, 위험·보장 공백 계산 결과를 대화와 연결
- [리스크 계산](lib/riskCalculator.ts), [보장 공백 계산](lib/gapCalculator.ts): 생성형 응답과 별도로 계산 로직 구성
- [약관 검색](lib/rag.ts): OpenAI 임베딩 키가 있을 때 관련 문서 조각을 찾아 대화 문맥에 추가
- [표현·범위 필터](lib/complianceFilter.ts): 범위 밖 질문과 일부 부적절한 표현을 처리하는 규칙 기반 장치
- [대화 화면](components/ChatInterface.tsx), [대시보드](components/DashboardPanel.tsx): 입력과 분석 결과 시각화

검색·필터는 보조 장치이며, 결과의 정확성이나 규제 적합성을 보증하지 않습니다.

## 제 기여와 AI 도구 활용

보험 진단과 상품 탐색을 분리한 사용자 흐름, 9단계 대화 구성, 정보 입력과 결과 화면, 시각화 방향, 프롬프트와 데이터 구조를 기획했습니다. 생성형 AI 코딩 도구의 도움으로 MVP 코드를 작성하고, 실행 과정에서 프롬프트 크기와 데이터 분리 문제를 조정했습니다. **코드 전체를 혼자 수작업으로 작성했다고 주장하지 않습니다.** 구현 범위와 의사결정 과정은 [작업 기록](WORK_LOG.md)과 [개선 로그](docs/개선_로그.md)에서 확인할 수 있습니다.

## 로컬 실행

Node.js와 npm이 필요합니다.

```bash
npm ci
npm run dev
```

브라우저에서 `http://localhost:3000`을 엽니다. 대화 기능에는 서버 환경 변수 `OPENROUTER_API_KEY`가 필요합니다. 코드의 현재 모델 설정은 OpenRouter의 `openai/gpt-4o-2024-08-06`입니다. `OPENAI_API_KEY`가 있으면 약관 검색에 임베딩을 사용할 수 있습니다. **키가 없으면 대화 API는 오류를 반환합니다.** 키를 Git에 올리지 마세요.

## 검증 상태와 한계

- 저장소에는 단계별 대화, 계산, 시각화 코드가 있습니다. 이 README는 배포 URL이나 현재 운영 상태를 검증한 것으로 표시하지 않습니다.
- 보험상품·통계 데이터의 최신성, 계산의 타당성, 개인정보 보호, 규제 준수는 별도 검증이 필요합니다.
- 평가·로그 API가 있어 실제 고객의 건강·재무정보를 입력하지 않는 것이 안전합니다.
- 수상 내역은 외부에서 확인할 증빙을 아직 확보하지 못해 이 소개에서 제외했습니다.
