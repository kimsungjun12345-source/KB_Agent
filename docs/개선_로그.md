### 2. LLM 모델 변경: Gemini Flash → GPT-OSS-20B

**배경:** 비용 절감 및 안정성 비교를 위해 모델 변경 테스트 진행.

**비교 결과:**

| | Gemini Flash | GPT-OSS-20B |
|---|---|---|
| Input 비용 | $0.10/M | $0.03/M |
| Output 비용 | $0.40/M | $0.11/M |
| 비용 차이 | 기준 | ~3.6배 저렴 |
| 컨텍스트 | 1M | 131K |

**로그 기반 품질 비교:**

| | Gemini Flash 세션1 | Gemini Flash 세션2 | GPT-OSS |
|---|---|---|---|
| Stage 진행 | Stage 2에서 루프 (19개 메시지) | 1→2→3→4→5 성공 | 1→2→3→4→5 성공 |
| 시각화 성공률 | 1/4 (25%) | 2/3 (67%) | 3/3 (100%) |
| 메시지 효율 | 19개 (반복 낭비) | 11개 | 7~9개 |
| 한국어 품질 | 양호 | 양호 | 양호 |

**판단:** GPT-OSS-20B가 비용 3.6배 저렴하면서 안정성이 더 높음. 시스템 프롬프트 ~5K 토큰 + 대화 ~5K 토큰 = ~10K 토큰으로 131K 컨텍스트 대비 충분. 모델 크기가 작지만, 계산은 Tool이 담당하고 LLM은 대화 흐름 제어/자연어 생성만 하므로 20B로 충분.

**변경:** `app/api/chat/route.ts` 모델을 `openai/gpt-oss-20b`로 변경 (2곳).

### 3. 빈 응답(답이 안 오는) 문제 해결

**증상:** 사용자가 입력해도 응답이 안 오는 현상이 자주 발생.

**원인 분석:**

```js
// route.ts:232 (수정 전)
if (choice.finish_reason === 'tool_calls' && choice.message.tool_calls?.length) {
```

GPT-OSS는 tool call을 수행해도 `finish_reason`이 `'tool_calls'`가 아닌 `'stop'`으로 반환하는 경우가 있음. 이 경우 tool call이 있는데도 무시하고 `choice.message.content`(빈 문자열)를 반환 → 프론트에 빈 응답 전달.

**해결:**

```js
// route.ts:232 (수정 후)
if (choice.message.tool_calls?.length) {
```

`finish_reason`이 아닌 `tool_calls` 배열 존재 여부로 판단하도록 변경. 추가로 빈 응답 fallback 메시지 추가.

### 4. Stage 2 반복 루프 문제 해결

**증상:** 리스크맵이 나온 후 "넘어가세요"라고 해도 또 리스크 점수를 반복 계산. Stage 3(갭 분석)으로 전환 안 됨.

**원인 분석:**

```js
// route.ts (수정 전)
if (effectiveStage === 2) {
  toolChoice = { type: 'function', function: { name: 'calculate_risk_scores' } };
}
```

프론트에서 `stage: 2`를 보내면 매번 `calculate_risk_scores` tool이 강제 호출됨. 리스크 점수가 이미 산출되었어도 다시 계산.

**해결:**

```js
// route.ts (수정 후)
const hasRiskMap = messages.some((m) => m.visualization?.type === 'risk_map') || allMsgText.includes('risk_map');
const hasGapAnalysis = messages.some((m) => m.visualization?.type === 'gap_analysis') || allMsgText.includes('gap_analysis');

if (effectiveStage === 2 && !hasRiskMap) {
  toolChoice = { type: 'function', function: { name: 'calculate_risk_scores' } };
} else if (effectiveStage === 3 && !hasGapAnalysis) {
  toolChoice = { type: 'function', function: { name: 'calculate_gap_analysis' } };
}
```

이전 대화에 해당 시각화가 이미 존재하면 tool_choice를 강제하지 않음.

### 5. 시각화 마커 파싱 실패 문제 해결

**증상:** LLM이 시각화 마커를 출력하는데 프론트에서 파싱 실패 (`has_visualization: false`).

**원인 분석:** LLM 출력 패턴이 일관되지 않음:
- `}]}### ###END_VISUALIZATION###` — JSON 뒤에 `###` 잔여물
- `}]} \n###END_VISUALIZATION###` — 공백 삽입
- ` ```json ###VISUALIZATION### ... ``` ` — 코드블록 감싸기

**해결:** `lib/parseResponse.ts`에 정리 로직 추가:

```js
// 마커 전후 공백/줄바꿈 정리
cleaned = cleaned.replace(/###VISUALIZATION###\s*/g, '###VISUALIZATION###');
cleaned = cleaned.replace(/\s*###END_VISUALIZATION###/g, '###END_VISUALIZATION###');
// JSON 끝과 마커 사이 잡문자 제거
cleaned = cleaned.replace(/(\}[\s\]]*\})#+\s*###END_VISUALIZATION###/g, '$1###END_VISUALIZATION###');
// JSON 파싱 시 트리밍
const jsonStr = visualizationMatch[1].trim().replace(/}[\s#]*$/, '}');
```

### 6. Recharts 애니메이션 무한 루프 에러 해결

**증상:** `Maximum update depth exceeded` 에러. `JavascriptAnimate` 컴포넌트에서 발생.

**원인:** Recharts 차트 컴포넌트가 데이터 갱신 시 애니메이션 setState를 반복 호출하여 React 업데이트 깊이 제한 초과.

**해결:** 4개 시각화 컴포넌트 전부 `isAnimationActive={false}` 추가:
- `RiskMap.tsx` — Radar 2개
- `GapAnalysis.tsx` — Bar 2개
- `ProductMatch.tsx` — Pie 1개
- `FinalReport.tsx` — Area 1개

### 7. 보험료 보간/환각 방지 (system-reminder에서 확인된 기존 개선)

**배경:** LLM이 20/30/40/50/60세 기준 보험료만 존재하는데 중간 나이(예: 32세)의 보험료를 임의로 보간하여 제시하는 문제.

**해결 (다층 방어):**
1. `system-prompt.ts` — "보간/추정 절대 금지" 명시 + "양쪽 구간 보험료 안내" 지시
2. `route.ts` — 상품 데이터 주입 시 "⚠ 위 보험료는 20/30/40/50/60세 기준에만 유효합니다" 경고 추가
3. `complianceFilter.ts` — `checkHallucination()` 함수: 비표준 나이 보험료 언급 감지 시 면책 문구 자동 추가, 금액 5% 이상 차이 경고
4. `evaluator.ts` — Rule 10 (premium_interpolation): 비표준 나이 보험료 언급 시 critical 이슈 플래그
5. `evaluator.ts` — Rule 11 (response_loop): 연속 응답 80% 이상 유사도 시 루프 경고
6. `evaluator.ts` — Rule 12 (empty_response): 빈 응답 감지
