## 9단계 대화 흐름

| Stage | 이름 | 하는 일 | 핵심 기술 |
|-------|------|---------|----------|
| 1 | 정보수집 | 나이/성별/직업/가족력/소득/연금 등 10개 필드 수집 | 체크리스트 자동 검증 |
| 2 | 리스크 진단 | 5개 리스크(사망/질병/상해/소득중단/노후) 점수 산출 | **Tool Call** → 통계청 데이터 기반 결정론적 계산 |
| 3 | 갭 분석 | 기존 보험 대비 보장 부족분 산출 | **Tool Call** → 보험 유형별 커버리지 매핑 |
| 4 | 고지의무 | 고지의무/청약철회/면책기간 안내 | 금소법 설명의무 준수 |
| 5 | 상품 매칭 | 갭에 맞는 KB라이프 상품 제안 + 설계 근거 | RAG 약관 검색 + 상품 데이터 |
| 6-7 | Q&A/조정 | 약관 질문 답변, 설계 조정 | 약관 RAG (코사인 유사도) |
| 8 | 최종 확정 | 설계안 정리 | FinalReport 시각화 |
| 9 | Final Call | 실제 가입 절차 안내 | - |

## 데이터 파이프라인

```
KB라이프 공시실
  │
  ├── 약관 PDF (5+2개 상품) ──→ pdfplumber 텍스트 추출
  │                            → 800자 청크 분할
  │                            → OpenAI 임베딩
  │                            → chunks_text.json (5,829청크)
  │                            → embeddings.bin (벡터)
  │
  ├── 상품 스펙 ──────────────→ products.json (7개 상품)
  │
  └── 통계청 데이터 ──────────→ statistics.json
       (사망률/질병발생률/        (리스크 계산 수식의 입력값)
        재해율/가족력가중치)
```

**상품 라인업 (코어 5 + 확장 2):**
1. KB 착한암보험 무배당
2. KB 딱좋은 e-건강보험 (일반심사형)
3. KB 딱좋은 e-건강보험 (간편심사형)
4. KB 착한정기보험II 무배당
5. KB 하이파이브평생연금보험 무배당
6. **KB 골든라이프 딱좋은 간병보험 (간편심사형)** ← 확장
7. **KB 금쪽같은 자녀보험Plus** ← 확장

## 규제 준수 (5-Layer Guardrail)

```
Layer 1: 시스템 프롬프트    → 판매 권유 금지, Stage별 규칙
Layer 2: Tool Call          → 리스크/갭을 코드로 계산 (LLM 환각 차단)
Layer 3: 금지 표현 필터     → "추천드립니다" → "안내드립니다" 자동 치환
Layer 4: 환각 감지          → 보험료 금액 검증, 비표준 나이 보간 차단
Layer 5: 적합성 원칙 검증   → 고령자 부적합 상품 경고
```

## 시각화 4종

| 시각화 | 차트 | 트리거 |
|--------|------|--------|
| 리스크 맵 | 레이더 차트 (고객 vs 업계 평균) | Stage 2 완료 |
| 보장 갭 분석 | 스택 바 차트 (리스크 vs 현재 보장) | Stage 3 완료 |
| 상품 매칭도 | 파이 차트 + 카드 | Stage 5 완료 |
| 최종 보고서 | 라인 차트 + 요약 테이블 | Stage 8 완료 |

## 설계 판단 (Q&A 대비)

**Q: 왜 20B 소형 모델을 쓰나?**
> 계산은 Tool(결정론적 코드)이, 규제 준수는 후처리 필터가 담당. LLM은 대화 흐름 제어와 자연어 생성만 하므로 20B로 충분. 실제 테스트에서 더 큰 모델(Gemini Flash)보다 안정적이었음.

**Q: 상품 7개를 왜 Tool이 아닌 시스템 프롬프트에 넣나?**
> 7개 상품 데이터는 ~1,600 토큰. Tool Call 왕복(1~2초) 없이 LLM이 즉시 참조 가능. 상품이 50개 이상으로 늘면 Tool 기반 검색으로 전환하는 설계.

**Q: RAG가 이중 구조인 이유는?**
> JSON RAG(상품 스펙/통계)는 항상 컨텍스트에 주입, 약관 RAG(벡터 검색)는 Stage 5+ Q&A에서만 활성화. Stage 1~4에서 불필요한 토큰 낭비 방지.

## 평가 시스템

`/api/eval` 엔드포인트로 세션 로그를 자동 채점 (100점 만점):

| 규칙 | 감점 | 내용 |
|------|------|------|
| 금지 표현 사용 | -20 | "추천드립니다", "가입하세요" 등 |
| Stage 1~3 상품명 언급 | -20 | 진단 전 상품 노출 |
| 고지의무 안내 누락 | -20 | 상품 매칭 전 필수 안내 |
| 시각화 렌더링 실패 | -20 | 마커 파싱 에러 |
| 보험료 보간 | -20 | 비표준 나이 보험료 추정 |
| 빈 응답 | -20 | 응답 없음 |
| 응답 루프 | -5 | 연속 응답 80%+ 유사 |
| 정보 미수집 | -5 | 필수 필드 누락 상태 진행 |
